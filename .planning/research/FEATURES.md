# Feature Research

**Domain:** Мобильный клиент к электронному школьному журналу (ИАС АВЕРС ЭКЖ v4.1) — iOS + Android, без backend
**Researched:** 2026-04-27
**Confidence:** MEDIUM-HIGH (АВЕРС-капабилити подтверждены официальной документацией; конкурентные фичи и UX-болевые точки — из публичных описаний и отзывов в App Store/Google Play; точный набор JSON-полей АВЕРС подтвердится только реверсингом, который — задача отдельной фазы)

## Контекст исследования

Это — feature-research для **клиентского** приложения школьного дневника, читающего данные из чужого backend (ИАС АВЕРС). Доступный потолок функциональности **ограничен сверху** тем, что реально отдаёт сервер АВЕРС. Снизу — конкурентным минимумом (что есть у ЭлЖур, Дневник.ру, СГО/NetSchool, МЭШ). Все фичи оцениваются ещё и по критерию «реализуема ли on-device без собственного backend» — это жёсткое архитектурное ограничение из PROJECT.md.

### Что предоставляет ИАС АВЕРС в роли «Родитель/Учащийся» (потолок)

По официальному руководству пользователя для роли «Родитель/Учащийся» v3.1 и описанию продукта v4.1, в системе три ключевые вкладки:

1. **«Дневник»** — список предметов, ФИО учителей, темы уроков, домашние задания (повторяет бумажный формат)
2. **«Оценки»** — текущие отметки и итоговые отметки за периоды
3. **«Сообщения»** — записи от учителей, классного руководителя, директора, завуча

Дополнительно из описания продукта подтверждены: **посещаемость** (отметки «Н»/«Б»), **итоги пропусков** (общее, по болезни, по периодам), **портфолио учащегося** (мероприятия, олимпиады, конкурсы), **отчёты по успеваемости/тематическому планированию**, **расписание занятий и замен**, **средний балл** (отображается в журнале учителя; вопрос — отдаётся ли для роли родителя), **запрос оценок по SMS** (внешний канал, не наш).

⚠️ **Не подтверждено в АВЕРС** (нужен реверсинг для уверенности): прогноз итоговой оценки с учётом весов, средний балл класса, мгновенный поток уведомлений, чат-формат сообщений с ответом, прикрепление файлов к ДЗ (упоминаются «прикреплённые файлы» в PROJECT.md как гипотеза).

## Feature Landscape

### Table Stakes (Users Expect These)

Без этого приложение воспринимается как «не работает» и удаляется. Все эти фичи присутствуют у всех конкурентов (ЭлЖур, Дневник.ру, NetSchool/СГО, МЭШ).

| Feature | Why Expected | Complexity | Notes (deps, on-device viability) |
|---------|--------------|------------|------------------------------------|
| Авторизация login/password АВЕРС с сохранением сессии | Без входа нет доступа к данным | LOW | Backend-dep: АВЕРС cookie/сессия; **on-device OK**. Нужен Ktor + cookie-jar |
| Просмотр текущих оценок за период | Базовая ценность дневника | LOW | Backend-dep: эндпоинт АВЕРС; **on-device OK**, кэшируется |
| Просмотр итоговых отметок | Дублируется во ВСЕХ конкурентах | LOW | Backend-dep: тот же эндпоинт; **on-device OK** |
| Расписание уроков на день/неделю с кабинетами | Самая частая операция в утро школьника | LOW-MED | Backend-dep: расписание + замены; **on-device OK**. Замены обязаны прокидываться явно |
| Замены в расписании (выделены визуально) | Без этого расписание врёт | LOW | Backend-dep: АВЕРС обязан отдавать факт замены; верификация на этапе реверсинга |
| Список домашних заданий по предметам со сроками | Вторая по важности фича после оценок | LOW | Backend-dep; **on-device OK**. Прикреплённые файлы — нужна загрузка binary, кэш на диск |
| Посещаемость (Н/Б, итоги пропусков) | Часть ожидаемой картины — родители проверяют пропуски | LOW | Backend-dep: «Н»/«Б» в журнале; **on-device OK** |
| Push-уведомления о новых оценках, ДЗ, заменах | Без push приложение «мёртвое», пользователи переходят на веб | HIGH (без backend) | **Полу on-device**. Без backend — фоновый polling: Android `WorkManager` (≥15 мин), iOS `BGAppRefreshTask` (несколько часов). Пуш через локальные уведомления. Декларация: «push когда ОС разрешит» |
| Биометрия / PIN на вход в приложение | Хранятся учётные данные ребёнка; ожидается всеми (МЭШ, СГО, ЭлЖур имеют) | MED | Device-only. iOS `LocalAuthentication`, Android `BiometricPrompt`. expect/actual в KMP |
| Безопасное хранение учётных данных | Чужие пароли — обязательно Keychain/Keystore | MED | Device-only. iOS Keychain, Android Keystore-EncryptedSharedPrefs |
| Оффлайн-доступ к последним загруженным данным | Школьники в метро, родители в офисе без сети | MED | Device-only. SQLDelight кэш + invalidate-on-fetch |
| Тёмная тема (следование системной) | iOS 13+ / Android 10+ — стандарт, отсутствие воспринимается как баг | LOW | Device-only. Compose Multiplatform: `MaterialTheme` + `isSystemInDarkTheme()` |
| Локализация на русский (родной язык школы) | Аудитория — российская школа | LOW | Device-only |
| Pull-to-refresh на всех списках | Нативный паттерн iOS/Android, ожидается интуитивно | LOW | Device-only |
| Корректное отображение учебного периода (четверть/триместр/семестр) | Школа №28 в Кирове — четверти; неверный период = неверный средний балл | LOW | Backend-dep: список периодов от АВЕРС. Жалоба №1 на конкурентов — «приходится вручную выбирать период» |

### Differentiators (Competitive Advantage)

То, чем мы можем отличаться от ЭлЖур/Дневник.ру/СГО — у них общая болезнь: «raw and inconvenient», нестабильность, плохие средние баллы, реклама и платная подписка за базовое.

| Feature | Value Proposition | Complexity | Notes (deps, on-device viability) |
|---------|-------------------|------------|------------------------------------|
| **Корректный средний балл** с учётом весов оценок | Жалоба №1 на ЭлЖур: «стоит одна 5, средняя 4,21». Жалоба на Дневник.ру: «оценки без предмета». Если мы считаем правильно — это сразу выделяет | MED | **On-device OK**. Сами считаем из массива оценок, не верим серверу. Нужна верифицированная формула (вес КР > вес домашней работы). Уточнить через диалог с учителем школы №28 |
| **Прогноз итоговой оценки** с учётом весов | Дневник.ру делает, ЭлЖур — формально да, на практике глючит. Это ключевой родительский запрос («сколько надо получить, чтобы вышла 4») | MED | **On-device OK**. Алгоритм: target_avg = (round_threshold × total_weight − current_sum) / remaining_weight. Реализуемо без сервера |

### Anti-Features (Commonly Requested, Often Problematic)

То, что выглядит хорошей идеей, но у нас явно не делаем — с обоснованием.

| Feature | Why Requested | Why Problematic | Alternative |
|---------|---------------|-----------------|-------------|
| Реклама / банеры | Монетизация free-приложений | EdTech privacy: 35% детских приложений high-risk из-за рекламных SDK; жалоба №1 на Дневник.ру; нарушает GDPR-K и 152-ФЗ | App Store / Google Play paid app или просто free без монетизации (низкие операционные расходы — нет backend) |
| Сторонние аналитики (Firebase Analytics, Amplitude, Facebook SDK, Yandex.Metrica) | «Понимать пользователей» | 83.6% детских приложений передают persistent IDs; нарушает Apple Privacy Manifest; родители всё чаще проверяют App Privacy / Data Safety | Локальный crash-log opt-in (Sentry self-hosted позже, или просто без аналитики в v1) |
| In-app purchases / платная PRO | Доход | Главная жалоба на Дневник.ру: «урезанная базовая до уровня, на котором нельзя нормально пользоваться» | Free навсегда, оплата вынесена в App Store как paid app или нет вовсе |
| Маячок / геолокация ребёнка | Фича Дневник.ру; родительский страх | Privacy-катастрофа: location-tracking детей через школьное приложение — это совсем другой класс рисков и согласий. 152-ФЗ прямо запрещает без явного согласия | НЕ делаем. Это задача семейных GPS-трекеров (Find My, Life360), не школьного дневника |
| Геймификация (баллы, бейджи, достижения за хорошие оценки) | «Мотивация ребёнка» | Превращает учёбу в игру за награды от приложения; педагогически спорно; раздувает scope; конкуренты не делают — потому что это не работает | Простой график динамики среднего балла (нейтральный визуал, без оценочных суждений) |
| Чат с учителями / родительский чат | «Удобно общаться» | АВЕРС отдаёт «Сообщения» в read-only формате (записи учителя). Реальный двунаправленный чат потребует реверсинга POST-эндпоинтов, модерации, риск-управления (что если ребёнок пишет учителю в 3 ночи?). Out of Scope явно отмечен в PROJECT.md | Read-only сообщения от учителя в v1. Чат — только если в v2 после оценки спроса |
| Учительский интерфейс (ввод оценок) | «Один app для всех» | PROJECT.md: out of scope. Совершенно другая роль, другие эндпоинты, другая ответственность за ошибку | Отдельное приложение если будет спрос. У ЭлЖур два приложения: «.Дневник» и «.Учитель» — это правильное разделение |
| Соц-фичи (профили учеников, лайки, ленты) | «Сделать школьную жизнь интерактивной» | Прямая privacy-проблема с детьми; out of scope EdTech-приложения; никто из конкурентов не делает | Не делаем |
| Глобальный поиск по всему приложению (оценки + ДЗ + сообщения) | «Удобно» | Без полнотекстового индекса (FTS5 в SQLDelight) — медленно. Польза низкая: в школьном дневнике контента мало | Поиск только в ДЗ (по предметам/датам) если будет нужно после v1 |
| Push мгновенный (как у мессенджеров) | Ожидание из мессенджеров | **Архитектурно невозможно без backend.** PROJECT.md: «принимаем задержки до нескольких часов на iOS» | Polling + локальные уведомления + честная декларация UX |
| OAuth / SSO / вход через Госуслуги | «Удобно» | АВЕРС не поддерживает OAuth, нечего интегрировать | login/password АВЕРС, как сейчас работает веб-версия |
| Облачная синхронизация настроек между устройствами пользователя | Стандарт удобства | Требует backend или Apple iCloud/Google Drive sync — добавляет сложность хранения зашифрованных credentials в облаке. Не критично для v1 | Локальные настройки на устройстве. Backup паролей — пользователь сам через iCloud Keychain (если включит) |
| Поддержка других школ / других АВЕРС-инсталляций в v1 | Маркетинг «масштабируемся» | Out of Scope явно: фокус на school28. Каждая инсталляция АВЕРС может иметь свои особенности. Конфигурируемый base URL — да, но активное обобщение — нет | Архитектура должна допускать; v2 решение |
| Поддержка ЭлЖур / Дневник.ру / СГО в одном приложении | «Универсальный клиент» | Out of Scope. Каждый — отдельный API, отдельные баги, отдельные ToS, отдельный риск-блокировки | Архитектурно совместимо с расширением, но v1 — только АВЕРС |

## Feature Dependencies

```
Авторизация login/password
    └── Безопасное хранение credentials (Keychain/Keystore)
         └── Биометрия / PIN на вход
              └── Мульти-аккаунт (множественные credentials)
                   └── Быстрое переключение между детьми (UI)

Просмотр оценок
    ├── Корректный учебный период (контекст)
    ├── Средний балл (вычисление on-device)
    │    └── Прогноз итоговой
    │         └── График динамики
    └── Цветовое кодирование оценок

Расписание уроков
    ├── Замены (явная маркировка)
    ├── Расписание звонков (обратный отсчёт)
    ├── Home Screen Widget (следующий урок)
    ├── Lock Screen Widget (iOS 16+)
    └── Экспорт в календарь (iCal)

Домашние задания
    ├── Прикреплённые файлы (download, кэш на диск)
    └── Экспорт в календарь (события-напоминания)

Push-уведомления
    └── Фоновый polling (WorkManager / BGAppRefreshTask)
         └── Локальные уведомления (NotificationManager / UNUserNotificationCenter)
              └── Smart-индикатор "новое" (last_seen_at)

Оффлайн-доступ
    └── SQLDelight кэш
         └── Все списочные экраны (оценки, расписание, ДЗ, сообщения)

Шрифт для дислексиков ──enhances──> Доступность всего UI
Тёмная тема           ──enhances──> Все экраны
Без сторонних SDK     ──enhances──> Privacy story / App Store review
```

### Dependency Notes

- **Биометрия требует Keychain/Keystore:** биометрический prompt разблокирует доступ к credentials в защищённом хранилище — без него хранение паролей бессмысленно слабее
- **Прогноз итоговой требует среднего балла + знание весов:** если АВЕРС не отдаёт веса — придётся либо хардкодить «дефолтные веса школы №28», либо отображать с дисклеймером «прогноз без учёта весов»
- **Замены в расписании требуют API-подтверждения:** если АВЕРС отдаёт замены отдельным флагом/полем — отлично; если нет — потолок функциональности заранее ограничен
- **Виджеты требуют shared storage** между app target и widget target (iOS App Groups, Android Content Provider) — это влияет на архитектуру SQLDelight-слоя
- **Экспорт в календарь конфликтует с push-уведомлениями** только в смысле UX-перегруза («у меня и нотификация, и событие в календаре про один и тот же ДЗ») — нужен toggle в настройках
- **Анти-фичи conflict с самим product positioning:** добавление аналитики SDK ломает differentiator «no third-party trackers» — это не просто «не делаем», это активная защита границ продукта

## MVP Definition

### Launch With (v1) — табличный минимум для жизнеспособности

Все table stakes + минимум differentiators, без которых нет смысла отличаться от веб-версии АВЕРС.

- [ ] **Авторизация login/password** + Keychain/Keystore — без этого нет доступа
- [ ] **Биометрия / PIN на вход** — обязательно, хранятся чужие пароли
- [ ] **Мульти-аккаунт** с быстрым переключением — ключевой differentiator из PROJECT.md
- [ ] **Текущие оценки** + **итоговые** + **корректный средний балл** — главная ценность; считаем сами, не доверяем серверу
- [ ] **Расписание уроков** на день/неделю с **кабинетами** и **заменами**
- [ ] **Домашние задания** с привязкой к датам и предметам
- [ ] **Посещаемость** (Н/Б, итоги пропусков по периодам)
- [ ] **Сообщения от учителя** (read-only)
- [ ] **Полноценный оффлайн** для всех вышеперечисленных экранов
- [ ] **Push-уведомления** через polling + локальные нотификации (с честной декларацией задержек)
- [ ] **Тёмная тема** + локализация RU
- [ ] **Pull-to-refresh** на всех списках
- [ ] **Без рекламы, без аналитики, без платных подписок** — это feature, не отсутствие фичи

### Add After Validation (v1.x) — после подтверждения базы

Добавляются после первого релиза, когда core-сценарии проверены реальными пользователями школы №28.

- [ ] **iOS Home Screen Widget** — следующий урок / след. ДЗ — триггер: пользователи спрашивают «есть ли виджет»
- [ ] **iOS Lock Screen Widget** — после Home Screen widget
- [ ] **Android App Widget** — параллельно iOS widget
- [ ] **Прогноз итоговой оценки** — триггер: запросы на калькулятор «что мне надо получить»
- [ ] **График динамики среднего балла** — триггер: пользователи хотят тренд
- [ ] **Расписание звонков** + обратный отсчёт — триггер: low effort, high delight
- [ ] **Экспорт в системный календарь (iCal)** — триггер: запрос «как в календаре с другими делами»
- [ ] **Шрифт для дислексиков** + регулируемый размер — триггер: accessibility-запрос (или proactive — мы знаем что в школе есть такие ученики)
- [ ] **Smart-индикатор "новое"** на оценках/ДЗ — триггер: low effort, заметный delight
- [ ] **Цветовое кодирование оценок** — параллельно динамическому графику
- [ ] **Поделиться оценкой/ДЗ** через системный share — триггер: запрос родителей

### Future Consideration (v2+) — если v1 валидирован и есть запрос

- [ ] **Поддержка других школ** на АВЕРС — после стабильного v1 на школе №28; требует конфигурируемый base URL и тестирование на других инсталляциях

- [ ] **Учительский интерфейс** — отдельный app, не v2 нашего

## Особо для нашего случая: реализуемость on-device без backend

Сводная таблица: что можно сделать без сервера, а что требует компромиссов.

| Feature | Backend нужен? | On-device viable? | Компромисс |
|---------|----------------|-------------------|------------|
| Авторизация, оценки, расписание, ДЗ, посещаемость, сообщения | АВЕРС-сервер (внешний, не наш) | Да — прямой HTTPS-клиент | Никаких. Это исходный план |
| Безопасное хранение credentials | Нет | Да — Keychain/Keystore | Никаких |
| Биометрия | Нет | Да — LocalAuthentication / BiometricPrompt | Никаких |
| Оффлайн-кэш | Нет | Да — SQLDelight | Stale data; маркируем «данные от: HH:MM» |
| Средний балл, прогноз, график динамики | Нет | Да — считаем локально | Никаких; даже лучше, чем у конкурентов (контроль формулы) |
| Push-уведомления мгновенные | Да (FCM/APNs proxy + сессия) | НЕТ | Polling + local notif; задержки до часов на iOS |
| Push при закрытом приложении | Да | Частично (BGAppRefreshTask, недетерминирован) | Принять задержки |
| Виджеты | Нет | Да — App Groups (iOS) / Content Provider (Android) | Никаких |
| Lockscreen widget iOS | Нет | Да — WidgetKit iOS 16+ | Только iOS 16+ |
| Экспорт в календарь | Нет | Да — EventKit / CalendarContract | Permission UX |
| Шрифт для дислексиков | Нет | Да — bundle font | Никаких |
| Чат с учителем (двунаправленный) | Внешний API АВЕРС, если поддерживает POST | Да, если эндпоинты найдутся | Реверсинг рисков |
| Мгновенная синхронизация между устройствами одного пользователя | Да | Частично (iCloud Keychain для credentials) | Локальный кэш на каждом устройстве независим |
| Аналитика, A/B, ремаркетинг | Да (или сторонний SDK) | Не делаем (anti-feature) | По дизайну отказались |

**Ключевой вывод:** ~90% запрашиваемой функциональности реализуется без собственного backend. Единственный реальный компромисс — push-задержки, и он принят осознанно в PROJECT.md.
